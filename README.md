## 📌 1. Problem Statement

India’s Q-commerce ecosystem — Zepto, Blinkit, Swiggy Instamart — runs on a bold promise: **groceries in 10 minutes.**  
But behind that promise is a worker like Ravi, operating within a strict **3 km delivery zone**, where even a small disruption can completely stop his income.

---

### ⚠️ The Ground Reality

- Q-commerce riders must **continuously stay on the road** — unlike food delivery riders who can wait indoors  
- A single disruption (rain, AQI spike, curfew, or hub shutdown) leads to **instant income loss**
- Each rider is tied to **one dark store** — if that zone is affected, they **cannot switch or relocate**
- Loss per disruption: **₹600–₹1,200**  
- Impact: **15–25% of weekly earnings**, often multiple times during monsoon  

---

### ❗ The Critical Gap

> **Event happens → Income stops → No protection exists**

- Existing insurance covers **health, not earnings**
- Current parametric systems:
  - Operate at **city level (too broad)**
  - Rely on **GPS (easily spoofed)**
  - Require **manual claims (too slow)**

## 🌍 5. Parametric Triggers

ArthaShield uses a **multi-signal parametric trigger system** designed for accuracy, fairness, and fraud resistance.

> ⚡ A payout is triggered only when:
> **Primary disruption threshold is breached + Secondary income/activity signal is confirmed**

---

## 🧠 Why This Matters

- Prevents **false payouts from generic city-wide alerts**
- Ensures **only real income loss is compensated**
- Keeps premiums **affordable and sustainable**

---

## ⚙️ Trigger Architecture (Dual-Gate System)

```
[ Disruption Event Detected ]
              ↓
[ Threshold Breach (Primary Check) ]
              ↓
[ Income / Activity Confirmation (Secondary Check) ]
              ↓
         → PAYOUT
```

---

## 📡 Trigger Signals

### 🌧️ 1. Extreme Rainfall

- **Source:** OpenWeatherMap API (zone-level coordinates)  
- **Threshold:**  
  - > 50 mm/hr for 30+ minutes  
  - OR > 100 mm in 24 hours  
- **Secondary Check:**  
  - Zero completed deliveries in Ravi’s zone  


---

### 🌫️ 2. Hazardous AQI (🆕 Differentiator)

- **Source:** OpenAQ API  
- **Threshold:** AQI > 300 sustained for 2+ hours  
- **Secondary Check:** Worker app status = ACTIVE  


---

### 🚫 3. Civic Disruption (Curfew / Strike)

- **Source:** Civic data API (GeoJSON boundaries)  
- **Threshold:** Zone overlaps with curfew/restricted area  
- **Secondary Check:** Worker active in last 2 hours  


---

### 🏪 4. Dark Store Hub Closure (🆕 Q-Commerce Specific)

- **Source:** Platform API (hub status)  
- **Threshold:** Hub marked OFFLINE / SUSPENDED  
- **Secondary Check:** Worker was recently active  


---

### 🚧 5. Flash Flood / Route Blockage

- **Source:** OpenStreetMap (Overpass API)  
- **Threshold:**  
  - All delivery routes blocked  
  - OR flood depth > 10 cm  
- **Secondary Check:** Active rainfall signal present

## 🚨 7. Adversarial Defense & Anti-Spoofing Strategy

### ⚠️ Market Reality

A coordinated fraud scenario can involve hundreds of workers using GPS spoofing tools to simulate presence inside a disruption zone — triggering false payouts at scale.

---

## 🔍 Our Core Shift

> Most systems ask:  
> **“Is the worker inside the disruption zone?”**

> ArthaShield asks:  
> **“Does the worker’s behavior match real-world activity?”**

---

## 🧠 Multi-Layer Defense Architecture

ArthaShield does not rely on a single signal like GPS.  
It validates **behavioral consistency across multiple independent signals**.

---

## 📱 Layer 1 — Multi-Signal Behavioral Verification

We analyze **6 independent device and activity signals**:

| Signal | Real Worker | Suspicious Pattern | Detection Logic |
|-------|------------|------------------|----------------|
| Accelerometer | Road vibration, speed changes | Near-zero variance | Motion classification (Riding vs Stationary) |
| Gyroscope | Tilts, turns, movement | Flat / static device | Angular variance check |
| Battery Usage | 2–4% drain / 30 mins | Minimal drain | Battery delta analysis |
| Cell Tower Handoff | Frequent changes (movement) | Static tower despite GPS movement | Tower vs GPS mismatch |
| Network Pattern | Signal fluctuations (4G/3G) | Stable WiFi / static IP | Network transition logs |
| Delivery App Activity | Active during work | Inactive / background | Platform API validation |


---

## 🤖 Layer 2 — Coordinated Pattern Detection (DBSCAN)

Fraud is often **group-based, not individual**.  
We detect coordinated activity using clustering:

### Detection Signals

- 📍 **Spatial clustering**  
  Multiple claims within a tight radius in a short window  

- ⏱️ **Temporal burst patterns**  
  Large number of claims within minutes  

- 📱 **Device similarity**  
  Same device models / OS versions concentrated  

- 🌐 **Network similarity**  
  Common ISP or network signatures  

- 🔢 **GPS precision anomalies**  
  Synthetic coordinate patterns vs real GPS noise  

- 🔁 **Cross-user correlation**  
  Repeated synchronized behavior across users  

---


---

## ⚖️ Layer 3 — Fairness & User Protection

> Fraud prevention should **not punish honest workers**

We implement a **risk-based decision system**:

| Risk Score | Action |
|-----------|--------|
| Low | ✅ Instant payout (< 60 sec) |
| Medium | ⏳ Soft Hold (auto-resolution within 2 hours) |
| High | 🔍 Manual review (resolved within 24 hours) |

- Claims are **held, not rejected**
